# SixSpec: The Origin Story

## The Discovery Path

### Background: Two Worlds Colliding

**10+ years as a developer** + **Elite NLP training (NLP Marin)** → Unique perspective on how systems change

After developing **synesthesia**, formed hypothesis:
> **"NLP models of human change might map isomorphically onto software development"**

### The Empirical Investigation

**Methodology**: Analyzed NLP training manual against software development practices, specifically Behavior Driven Development (BDD)

**Result**: **85%+ parallel practices identified**

The 15% gap? Limited sensory channels in software (no gustatory, kinesthetic, olfactory—only visual/auditory/linguistic representations).

**This isn't metaphor. This is mathematical isomorphism.**

### The "Aha!" Moment

Remembered **Dilts' Neurological Levels** (foundational NLP model):
```
Mission/Spirituality  →  FOR WHAT / Connection to larger systems
Identity              →  WHO / Self-concept and role
Beliefs/Values        →  WHY / Guiding principles and meaning
Capabilities          →  HOW / Skills and strategies  
Behaviors             →  WHAT / Observable actions
Environment           →  WHERE/WHEN / Context and constraints
```

### The Connection to Enterprise Architecture

Compared to existing frameworks → Discovered **Zachman Framework** (enterprise architecture standard)

**Revelation**: Dilts' (Neuro)logical Levels ≅ **Organizational Entity Schemas**

| Dilts Level | Maps To | Autonomy | Question |
|-------------|---------|----------|----------|
| Mission | Enterprise Purpose | Extreme | FOR WHAT purpose? |
| Identity | Organizational Identity | High | WHO are we? |
| Beliefs | Business Rules/Principles | Moderate | WHY this way? |
| Capabilities | System Capabilities | Low | HOW do we operate? |
| Behaviors | Processes/Functions | Very Low | WHAT do we do? |
| Environment | Physical/Technical Context | Zero | WHERE/WHEN does this happen? |

**Not an analogy. A structural equivalence.**

## What This Means

### 1. NLP is a Meta-Model of Change

NLP practitioners observed what worked in therapy/change work and formalized it. These patterns aren't specific to humans—they're **patterns of how hierarchical systems organize and transform.**

### 2. Software Development is a Special Case

Software development is **intentional system change**. The same structural patterns that govern:
- Therapeutic change (NLP domain)
- Organizational change (Zachman domain)
- Personal transformation (Dilts levels)

...also govern:
- Software architecture
- Development workflows  
- Agent coordination

### 3. W5H1 is Universal Dimensional Framework

The six questions (WHO/WHAT/WHEN/WHERE/HOW/WHY) aren't arbitrary:

**They map to fundamental aspects of representation:**
- **WHO**: Agent/actor (subject)
- **WHAT**: Action/object (predicate/object)
- **WHEN**: Temporal dimension
- **WHERE**: Spatial dimension
- **HOW**: Process/method
- **WHY**: Purpose/cause

These are **cognitive primitives**—the minimum dimensions needed to fully represent any action or specification.

### 4. The Autonomy Gradient Isn't Arbitrary

In Dilts' model, higher levels have more influence over lower levels (downward causation). Lower levels cannot directly affect higher levels.

**This maps exactly to organizational hierarchy:**
- Mission/strategy sets direction (high autonomy)
- Identity/culture constrains choices
- Beliefs/values guide decisions
- Capabilities enable actions
- Behaviors execute
- Environment provides constraints (zero autonomy)

**And to software architecture:**
- Strategic goals drive system design
- System identity defines core capabilities
- Architectural principles constrain implementation  
- Technical capabilities enable features
- Features implement specific behaviors
- Infrastructure provides execution context

### 5. WHAT→WHY Propagation Isn't a Trick

**It's how meaning propagates through hierarchical systems.**

In NLP:
- "I want to lose weight" (Behavior)
- WHY? "To be healthy" (Capability)
- WHY? "To feel confident" (Belief)
- WHY? "To connect with others" (Identity)
- WHY? "To contribute to community" (Mission)

In Software:
- "Write WebhookController" (Environment)
- WHY? "Implement Stripe webhooks" (Behavior)
- WHY? "Integrate payment processing" (Capability)
- WHY? "Enable premium subscriptions" (Belief)
- WHY? "Launch premium tier" (Identity)
- WHY? "Achieve market leadership" (Mission)

**Same pattern. Same structure. Same mechanism.**

## Research Implications for Anthropic

### 1. Multi-Agent Coordination Should Follow Dilts Levels

If these patterns are universal to hierarchical systems:

**Hypothesis**: AI agent teams should organize with:
- Strategic agents at Mission/Identity levels (high autonomy)
- Tactical agents at Capability/Behavior levels (low autonomy)
- Execution agents at Environment level (zero autonomy)

**Prediction**: Flat agent architectures will struggle. Hierarchical architectures following Dilts patterns will coordinate more effectively.

**Test**: Build agent teams both ways, measure coordination efficiency.

### 2. Chain-of-Thought Should Map to WHAT→WHY

Current LLM reasoning is often disconnected.

**Hypothesis**: Structuring reasoning with explicit WHAT→WHY propagation will:
- Improve coherence
- Enable better interruption/resume
- Make reasoning traceable
- Allow agents to explain decisions

**Test**: Compare LLM reasoning with/without dimensional structure.

### 3. Context Windows Should Be Dimensionally Structured

Current context: Linear token stream

**Hypothesis**: Structuring context as W5H1 dimensions will:
- Compress information more efficiently
- Enable targeted retrieval
- Preserve meaning better
- Scale to larger contexts

**Test**: Compare dimensional context vs linear context on same tasks.

### 4. Agent Confidence Should Be Per-Dimension

Current: Single confidence score per output

**Hypothesis**: Tracking confidence per dimension (WHO: 0.9, HOW: 0.4, WHY: 0.7) will:
- Identify uncertainty more precisely
- Enable better collaboration (high-confidence agent handles uncertain dimensions)
- Guide research/validation efforts

**Test**: Per-dimension confidence vs aggregate confidence.

### 5. Portfolio Execution is How LLMs Should Explore

Current: Generate one solution, maybe with variations

**Hypothesis**: Portfolio approach (generate N solutions, validate empirically, pick winner) will:
- Reduce overconfidence errors
- Find better solutions through exploration
- Align with ML mindset (measure > predict)

**Test**: Portfolio vs single-shot on complex problems.
